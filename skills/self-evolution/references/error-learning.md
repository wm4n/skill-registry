# 錯誤學習流程

被使用者糾正時執行。目標：同樣的錯不犯第二次——最好是**犯不了**。

## 流程

### 1. 根因分析

不是記「我做錯了 X」，而是問：「**為什麼我當時會認為那樣是對的？**」

- 錯誤的假設？（我以為 A，實際是 B）
- 缺失的檢查？（動手前少確認了什麼）
- 知識空缺？（不知道存在某規則／工具／慣例）

### 2. 二犯檢查

查 `~/.claude/evolution/INDEX.md`：這次違反的是不是**已記錄的教訓**？

- 是 → 規則本身寫得不夠有效。這條教訓在步驟 3 **必須至少往上一層**（文字 → 流程步驟或機制）；真的做不到，在 lessons 檔寫明原因。lessons 檔標記「二犯」+ 日期，INDEX 狀態改 `repeated`，接著從步驟 3 更新既有記錄
- 否 → 繼續步驟 3

### 3. 放置

讀 [placement.md](placement.md)，決定**範圍**（全域／技術棧／repo／個人 × repo）與**強制層級**（機制 → 流程步驟 → 規則檔 → 常駐條目）。先問能不能做成機制，做不到才往下。

### 4. 寫規則

- **機制**：依 placement.md 的安裝方式做（repo lint 直接做在獨立 commit；全域 hook 只寫草稿等核准）
- **文字規則**：一條可執行的規則，「做 Y 之前先確認 Z」。「要更小心」「注意 X」是空話，退回重寫

機制還沒生效前（hook 等核准中），文字規則照樣寫入，生效確認後再依 placement.md 移除。

### 5. 寫紀錄

a. 寫 `~/.claude/evolution/lessons/YYYYMMDD-<slug>.md`（每條教訓都寫，不論範圍）：

```markdown
# <一行標題>

- 日期：YYYY-MM-DD
- 情境：<發生什麼事，2-3 句>
- 使用者糾正：<原話或摘要>
- 根因：<步驟 1 的結論>
- 防範規則：<步驟 4 的規則>
- 範圍：全域／技術棧（<stack>）／repo（<repo 名>）／個人 × repo
- 強制方式：<機制位置／流程步驟所在 skill／規則檔路徑／常駐條目 + 上一層做不到的理由>
- 最後引用：YYYY-MM-DD（快篩第 0 題命中或被違反時更新）
- 二犯記錄：（無 / YYYY-MM-DD + 改寫說明）
```

b. 依範圍與層級寫入文字規則：CLAUDE.md 區塊條目（格式見 placement.md）、或規則檔、或 auto-memory。

c. `INDEX.md` 的 Lessons 區加一行：`- [狀態] <標題> — YYYY-MM-DD — lessons/YYYYMMDD-<slug>.md`，狀態依層級填 `active`／`scoped`／`enforced`。

### 6. 驗證

跑檢查腳本（見 SKILL.md「檢查腳本」），exit 0 才算完成。輸出 `REVIEW_DUE` → 接著走 [review.md](review.md)。

## 完成後

向使用者一句話報告：「已記錄教訓 [Exxx]：<摘要>（範圍／強制方式）」；有待核准的 hook 草稿時附路徑。
