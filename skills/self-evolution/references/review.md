# 教訓複審

教訓會過時：工具換了、情境不再出現、模型預設行為已涵蓋、或已有機制強制。複審讓常駐條目只留下仍在發揮作用、且無法往上做的那些。

## 觸發

任一成立即執行：

- 檢查腳本輸出 `REVIEW_DUE`（常駐條目超過 20 條、有條目超過 60 天未引用、或有 lessons 檔缺 `強制方式`）
- 使用者要求 `/self-evolution review`

## 流程

### 1. 盤點

跑檢查腳本（見 SKILL.md「檢查腳本」），再讀 INDEX 中所有 `active`、`repeated`、`scoped` 教訓的 lessons 檔。複審範圍是**全部**這些教訓，不只被標為過期的。

### 2. 逐條判定處置

每條選一個：

| 處置 | 適用 |
|---|---|
| 保留 | 仍在發揮作用，且是無法往上做的 agent 行為；`最後引用` 改成今天 |
| 做成機制 | 違規能被 lint／測試／hook 擋下 → 依 [placement.md](placement.md) 安裝 |
| 搬層 | 實為技術棧或 repo 的事實 → 移到對應規則檔 |
| 嵌入流程 | 只在某個使用者自己維護的 skill 的情境發生 → 寫成該 skill 的步驟 |
| 合併 | 跟另一條講同一件事 → 併入較新的那條，舊檔補「已併入 <檔名>」 |
| 封存 | 工具或情境已不存在、跟其他章節重複、或模型預設已這麼做 |

缺 `強制方式` 的 lessons 檔，判定時一併補上。

### 3. 使用者確認

把判定列成一張表（條目、處置、一句理由）給使用者，**一次確認全部**。封存、搬層、嵌入流程會改變 agent 常駐的行為，使用者沒點頭的條目維持原狀。

### 4. 執行

依核准的處置更新 lessons 檔、INDEX 狀態、CLAUDE.md 區塊、規則檔。機制類依 placement.md 的「生效確認」走完才移除常駐條目。

### 5. 驗證

跑檢查腳本。**完成條件**：每條在盤點範圍內的教訓都有處置，且檢查腳本 exit 0、不再輸出 `REVIEW_DUE`（未核准而維持原狀造成的除外，向使用者說明）。

## 完成後

向使用者回報：常駐條目數（前 → 後）、各處置的條數、待核准的 hook 草稿路徑。
